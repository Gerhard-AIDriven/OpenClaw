# Skill: Windows API Caller (Standardized)

## Description
A standardized procedure for performing HTTP API requests on Windows hosts using PowerShell. This method avoids the common "quoting hell" and argument-splitting issues encountered when using `curl` directly in a shell, and bypasses default script execution restrictions.

## Trigger
Use this pattern whenever an API call (REST/JSON) needs to be made via the shell on a Windows host.

## Procedure

1. **Write Request Script**:
   Create a temporary `.ps1` file in the workspace. Use a PowerShell hash table for the payload and `ConvertTo-Json` to ensure perfect JSON formatting.
   
   Example content:
   ```powershell
   $body = @{
       key1 = 'value1'
       key2 = 'value2'
   }
   $json = $body | ConvertTo-Json
   Invoke-RestMethod -Uri 'http://endpoint' -Method Post -ContentType 'application/json' -Body $json
   ```

2. **Execute with Bypass**:
   Run the script using the following specific command to override the default execution policy:
   `powershell -ExecutionPolicy Bypass -File <path_to_script>.ps1`

3. **Capture Output**:
   Read the standard output of the command. If the output is a complex object, ensure the script specifically returns the property needed (e.g., `$response.listing_text`) to avoid console truncation.

4. **Cleanup**:
   Delete the temporary `.ps1` file after the result is successfully captured.

## Constraints
- **Security**: Only use `-ExecutionPolicy Bypass` for scripts generated by the agent within the trusted workspace.
- **Formatting**: Always use `ConvertTo-Json` rather than manually constructing JSON strings to prevent syntax errors.
- **Completeness**: Ensure the final output displayed to the user is the full, unabridged response from the API.

## Tooling
- `write`: To create the `.ps1` file.
- `exec`: To run the `powershell -ExecutionPolicy Bypass` command.
- `edit` or `exec (rm)`: To clean up the temp file.
